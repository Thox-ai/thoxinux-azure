Acceptance boundary. Actual local QEMU execution of the released kernel and embedded-domain lifecycle. Azure deployment, production service, native Hyper-V, a graphical desktop and MeshStack were not tested. Rootfs pending does not establish ready Rocky Linux or systemd userspace.

Repeat the real local test

Use a Linux host with Python 3.11 or newer. Install the packages below, then run the verifier from the repository root as an ordinary user. Use a new output directory; the verifier refuses root execution and existing output paths.

sudo apt-get update
sudo apt-get install --yes qemu-system-x86 ovmf util-linux
python3 tools/verify_kernel.py --output /tmp/thoxinux-proof-01

1. Verify pinned inputs

The verifier downloads the v0.9.1 release assets, verifies their expected bytes and manifest, and checks the bundled upstream launcher before starting QEMU.

2. Exercise the actual guest

A temporary state directory holds two real boots, eight controller checks, 22 embedded-domain commands and clean shutdowns. Temporary processes are cleaned up.

3. Inspect the saved proof

Review summary.json, both lifecycle result files, running/stopped receipts, complete serial.log and supervisor logs in the selected output directory.

4. Evaluate Azure separately

Follow Quickstart for the Azure deployment. The Azure acceptance extension must verify the live service and guest before that deployment can be accepted.

Source and proof

The deployment package version and the kernel release are separate. The recorded EFI is v0.9.1; its actual banner remains ThoxInux 0.9.0. This preview does not certify a package release or cloud deployment.
